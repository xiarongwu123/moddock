# 千款游戏适配目标与当前交付

目标是至少 1000 款主流游戏有可执行 Mod 制作能力。**本次交付尚未达到这一目标。**

当前接入本地 Nexus 目录，共 5508 条游戏记录（去重数量以 API 实际返回为准）。来源和抓取日期随记录保留。它用于检索与安排适配，所有目录记录初始为 `unassessed`；目录数量不当作可制作数量。联网或保护限制不通过引擎猜测绕过。

新增功能：

- 本机手动游戏容量由 50 提升至 10000；扫描发现的游戏照常合并。
- `POST /api/studio/catalog`：`{query,offset,limit}`，每页最多 100 条，支持游戏名与 Nexus 域名搜索。沿用本地会话、CSRF 和 Pro 权限。
- `POST /api/studio/coverage`：`{offset,limit}`，对服务端扫描出的真实游戏逐款读取诊断；每页默认 32、最多 100，最多两款并发。单款错误单独报告，支持 `nextOffset` 分页；请求不能指定任意文件路径。
- 工作台选游戏页新增本机适配检查、检查进度、结果列表与停止检查。停止会在当前批次结束后生效。检查不消耗模型 token，不修改游戏文件。
- 单款 workspace 返回 `coverage`，与批量接口共用同一套判断。

状态含义：`authoring-route` 表示存在专用脚本/内容制作入口；`engine-investigation` 表示需要进一步读取本机代码并解决工具、资源或加载条件；`missing-adapter` 表示尚缺制作路线；`blocked` 表示存在联网或保护限制；`diagnostic-failed` 表示无法读取。前两项均不等同于构建或安装成功。具体产物仍需通过构建、安装检查与用户对当前构建的效果确认；仍保留原有入库门槛。

## 本机批量报告

使用 Node 22.19 以上版本：

```powershell
node scripts/audit-studio-games.cjs games.json coverage-report.json
```

输入为扫描结果 `{games:[...]}` 或游戏数组，包含正常扫描所用的身份和 `installPath`。输出文件必须不存在，避免覆盖历史证据。报告分别保留目标数、目录数、检查数、各状态数及逐款结果，`targetVerified:false`，不会把批量流程测试提升成千款游戏实机验收。

## 尚需完成

现有六类引擎开发路径可用于名单外游戏，但不能仅由引擎相同推断任何玩法需求都能实现。接下来需逐款确认主流游戏的发行版本、合法加载方式、可编译接口和可安装产物；缺少工具链的游戏补专用路线。游戏内验证需针对实际游戏和当前构建保存证据，不能用伪造名字或同一模板复制 1000 次替代。

本次千条测试只验证分页、并发边界、身份独立、错误隔离及状态语义；既有专用路线与引擎回归另行执行。没有新增 1000 款游戏的实机验证，没有部署 MU 后端或替换已安装客户端。
