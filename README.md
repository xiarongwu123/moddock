# 游匣 Moddock v0.5.0

Windows 本机游戏库、社区 Mod 浏览下载与按游戏规则安装管理应用。

## Windows 启动

下载 `moddock-windows-x64.zip`，右键“全部解压”，打开 `Moddock` 文件夹，运行 `Moddock.exe`。
保留所有伴随文件；无需安装 Node.js。Windows 10 / 11 x64。Windows 运行包已构建，尚未在 Windows 实机验证。

## 操作流程

1. 启动时自动扫描 Steam / Epic 安装记录。点击“扫描本机游戏”重新扫描；设置中可添加 Steam 安装目录或 Steam 库目录。
2. 进入扫描到的游戏，软件内查询 Nexus Mods、GameBanana 与 Steam 创意工坊，查看列表与总数。
3. 输入 Mod 名或关键词进行当前游戏范围的搜索。通过来源标签筛选，点击“加载更多”分页读取。不会一次把全部资源下载到本地。
4. 点击 Mod 查看描述、前置要求（来源提供时）及文件列表，选择文件后加入软件内下载队列。
5. 在“下载管理”查看进度、取消、重试、打开文件所在位置或另存。下载记录在重启后保留；未完成任务会标记中断，可重新下载。

没有本机游戏时显示空游戏库；不再提供演示游戏、演示 Mod 或独立三站资源页。

## 三站支持范围

- **Nexus Mods**：使用官方 GraphQL API，按游戏专区查询全库公开 Mod，支持关键词搜索、总数和分页。详情、前置及文件列表在软件内显示。连接 API Key 后请求官方下载链接，获得下载授权的文件由软件直接下载。普通账号可通过软件内官方 Nexus 网页点击 Mod Manager Download，接收 NXM 文件级临时授权，再由本机下载队列下载。支持 Windows 协议回传与设置中粘贴链接；API Key 与网页账号必须一致。尚未用真实账号验证完整签发流程及 Windows 系统协议回传。Premium 账号接口仍受站点与文件权限限制。
- **GameBanana**：按游戏查询和搜索公开 Mod，软件内获取详情、文件列表与直接下载。已实测从 GameBanana 下载真实 ZIP 文件，校验来源 MD5、文件大小及本地 SHA-256。
- **Steam 创意工坊**：按 Steam App ID 查询公开列表；可在设置输入 Steam Web API Key 使用官方查询接口。公开详情接口提供下载直链时，由软件下载。没有公开地址的现代工坊资源，需要 Steam 客户端授权通道，当前版本尚未接入。当前网络无法访问工坊列表，查询与无直链状态经过接口模拟测试，未验证 Steam 账号实时查询或文件下载。

资源列表、详情、下载队列、文件校验和安装管理在本软件完成。Nexus 的登录及文件授权在独立的软件内官方网页窗口完成；网站仍可能要求验证码或下载确认。来源不支持或需要权限时，软件显示具体原因，不会伪装成功。

自动匹配使用 Steam App ID、已知专区映射及游戏英文名的唯一匹配。不能唯一匹配时，可在游戏内“来源匹配”填写 N 网专区名、GameBanana 游戏 ID、Epic 对应 Steam App ID。无法保证所有本机游戏在每个站点都有 Mod 专区。

## v0.4.0 游戏专属安装与管理

所有扫描到的游戏都可以建立自己的安装规则，并非只允许几款游戏安装。**这不等于所有游戏、任意 Mod 都能自动适配或保证生效**：规则需要符合该游戏和该包的作者说明。未知游戏在游戏详情或下载管理中打开“安装规则”。

1. 下载完成后点击“安装”。没有规则时在软件内查看包内实际文件，设置游戏内容根目录、包内目录、目标目录、前置文件和游戏/加载器启动入口。所有路径均为相对目录，不接受越出扫描游戏目录的写入。
2. 安装方案列出每个源文件 → 目标文件，标明新建或已有文件覆盖。核对作者说明；覆盖已有文件必须明确勾选备份替换。
3. 安装时再次检查游戏路径、前置、游戏进程、文件冲突、下载 SHA-256 和暂存文件哈希。替换前备份原文件，记录每个托管文件和目标哈希。
4. “Mod 管理”支持启用、停用、卸载和校验。停用/卸载还原被替换的原文件，移除自己新增的文件；保留游戏或 Mod 后续生成的未托管文件。托管文件被外部修改时拒绝操作并列出路径，避免误删用户改动。此时先保留改动，恢复记录中的文件版本后重试；本版没有强制覆盖按钮。
5. 游戏详情或 Mod 管理点击“启动并验证/运行验证”。启动配置的本机原生游戏/加载器入口，检查托管文件；点击“检查本次运行”读取进程和本次日志。可以配置相对日志路径及实际加载成功标记。SMAPI 自动读取其标准日志，并匹配本次 Loaded mods/content packs 列表中的托管 Mod 名称和版本。

### 安装规则类型

| 规则 | 实际行为与要求 |
| --- | --- |
| 目录映射 / 原文件替换 | 适用于任意游戏可按目录部署的 ZIP；可选包内目录，保持其子目录结构，支持备份替换。例如 XNB 替换包可指定包内内容目录映射到游戏 Content。必须按作者说明配置。 |
| SMAPI 清单包 | 找出 manifest.json，检查 UniqueID、入口 DLL、必需依赖/版本、清单声明的最低版本；部署到 Mods/UniqueID。阻止重复 ID、依赖缺失、停用被其他启用 Mod 依赖的项；重新启用时再次检查依赖。星露谷有内置目录预设，SMAPI 必须先正确安装；本版不代替官方 SMAPI 安装程序。 |
| 纯 archive 包 | 只部署 archive 文件，验证 RDAR 头，忽略文档/图片，混合其他框架文件则拒绝。赛博朋克 2077 有 archive/pc/mod 目录预设；不是 REDmod/ArchiveXL/REDscript 等框架安装器。 |
| Unreal pak/utoc/ucas | 将对应数据文件按文件名放入你配置的游戏 Mod 目录。引擎版本、签名、配套文件、游戏是否开放 Mod 加载需要按作者说明确认，不能只凭扩展名判断可用。 |
| BepInEx 插件目录 | 按配置的包内目录 → 目标目录部署，检查 BepInEx/core/BepInEx.dll 存在；BepInEx 本身的游戏版本、架构、IL2CPP/Mono 配置仍需正确。本版不会代装加载器或自动识别所有插件依赖。 |

支持 ZIP 和独立 archive/pak/utoc/ucas；**RAR、7z、FOMOD 交互安装器、脚本安装、需要外部部署工具的包仍需专用适配**。软件不执行下载包内的脚本或安装器。内置目录预设只是便捷规则，不是全 Mod 兼容认证。同一游戏存在多种安装机制时可以通过“包内目录/目标目录”分别选择；每游戏保存当前默认规则；每项已安装 Mod 单独保存安装时的规则快照。可以调整默认规则，为下一种格式生成方案，已有 Mod 仍按自己的规则停用或卸载。跨规则碰撞到同一目标文件时仍拒绝安装。

### 校验与恢复

- 解压限制：最多 12000 条目，合计 4 GB，ZIP 单条目 1 GB，大文件压缩率最多 500 倍；验证 ZIP CRC/展开大小、拒绝链接、路径穿越、Windows 保留名、大小写重名。大量更大 Mod 包目前会明确拒绝。
- 同目标文件的托管 Mod（包括停用项）互相排斥；本版不做冲突排序、自动合并或覆盖栈。同一下载项再次安装、SMAPI 重复 ID 会阻止；更新通过卸载旧版再安装新版。
- 写入使用临时文件、事务日志和原文件备份。中途失败回滚；下次启动恢复未完成事务。回滚期间发现外部文件改动则保留日志和备份，停止自动恢复并报告原因。文件系统损坏、进程竞争或突然断电仍无法保证无损；不要同时用多个 Mod 管理器改同一目录。
- **文件部署成功 / 文件校验通过 / 进程运行中 / 日志确认加载 / 游戏内效果确认分开表达**。进程正常或通用日志标记出现不能保证每个 Mod 生效；需要存档、场景、版本等实际游戏条件。本版没有自动游玩检查。
- Windows 用系统进程列表检查游戏路径和已配置入口，无法读取部分受保护进程的路径时可能漏检；请退出游戏再部署。需管理员权限的游戏目录会报告权限错误，不自动提权。
- 安装记录、载荷和原文件备份在数据目录 installations 中，启用/停用和重启后保留。正常卸载后移除该项载荷/备份；不删除未托管文件或非空游戏目录。

验证：自动检查（临时目录实际文件操作）及 `node test/ui-installations.cjs` 完整界面流程通过。**尚未在 Windows 实机或实际游戏中验证 Mod 效果**。这些检查证明部署与恢复逻辑，不代表所有游戏和 Mod 兼容。

## 数据与下载

桌面版：Electron 用户数据目录下的 `data`，具体下载目录在设置中显示。
网页预览：项目 `.moddock-data`。可通过 `MODDOCK_DATA` 指定数据根目录。

最多同时下载 3 个文件、队列 20 项，单文件上限 5 GB。临时文件以 `.part` 保存，完成后校验大小，生成 SHA-256；来源提供 MD5 时比对。失败或取消清理未完成文件。

密钥只保存在本地服务内存中，退出后清除，不写入设置、下载历史或返回给界面。下载直链在服务端取得，不接受用户输入的任意 URL；重定向验证允许的 HTTPS 来源域名；拒绝网页或 JSON 伪装的下载内容。

## 源码运行

### MU 账号登录与注册

启动后先展示登录页。登录按“邮箱 → 密码”分两步，注册按“邮箱 → 密码 → 邮箱验证码”分三步，每步只有一个输入框，可返回上一步修改。步骤切换使用约 330 毫秒的滑动和淡入淡出，返回时反向播放；动画期间阻止重复提交，结束后聚焦当前输入框，系统减少动效时直接切换。登录与注册在同一卡片内切换，保持页面地址、卡片尺寸和背景；保留密码显隐、验证码错误清空和重发倒计时。完整验证码验证通过后自动注册，并用 React Bits `GridScan` 进入首页，无需再点击确认。必须登录后才能使用，首页侧栏的返回按钮会退出登录并回到账号入口。

账号界面只在输入错误、验证码过期或处理中显示当前提示。验证码步骤的 `?` 可主动展开收件帮助和有效期，再次点击或按 Escape 收起，帮助不会改变卡片尺寸。注册前需勾选用户协议和隐私政策，桌面版通过系统浏览器打开 MU 的协议页面。

登录的“输入密码”步骤提供“找回密码”。找回流程沿用分步卡片：确认邮箱 → 新密码 → 确认新密码 → 邮箱验证码，发送验证码使用 MU 的 `purpose: reset`，完整验证码填写后提交 `auth/reset-password`。密码需 8–128 位，两次一致；发送失败和验证码错误保留已填写内容，返回修改时保留原验证码及重发倒计时。重置成功后清空密码并返回同一邮箱的登录密码步骤，提示使用新密码重新登录，不会自动进入游戏库。

默认复用 `https://mu-api.claude-api.cn/` 的 MU 账号服务，已有 MU 账号可直接登录。密码为 8–128 位，邮箱验证码有效期 10 分钟，重发倒计时遵循服务端响应。发送验证码调用 `POST /api/v1/auth/code`（`purpose: register`）；填写完整验证码后直接调用 `POST /api/v1/auth/register`，由 MU 验证并创建账号，无单独验证码校验接口。登录调用 `POST /api/v1/auth/login`。错误密码、验证码无效、限流、账号停用和维护提示使用服务端状态与文案。

React 入口为 `src/main.jsx`，认证适配器为 `src/auth/client.cjs`。`account.cjs` 经本地服务代理 MU 请求，避免浏览器跨域；MU 令牌不返回界面，密码不保存。默认仅在服务内存中保存会话；桌面版可通过 `remember: true` 将刷新令牌保存到系统加密缓存，保存失败会返回提示。界面仅持有 HttpOnly / SameSite Cookie 对应的随机会话标识。页面刷新会校验账号，访问令牌即将到期或返回 401 时串行刷新；退出、改密和密码重置会清除对应会话。本地业务接口和 NXM 接收均要求登录，关键操作按 MU 的游戏库、配置和启动权限实时授权。原生游戏库由 `public/app.js` 提供挂载/卸载入口。

登录后可从顶部账号菜单打开“个人中心”，以可拖动、翻面的挂绳卡片查看 MU 邮箱、账号名称、用户 ID、会员等级及有效期；每次打开时刷新账号信息。弹窗打开时暂停游戏库轮询，关闭后恢复，支持 Escape、关闭按钮和点击背景退出，并将焦点归还账号菜单。退出登录也位于账号菜单。界面使用 `src/account/UserCenter.jsx` 与账号状态模块 `src/account/store.cjs`。

用户系统功能层还提供完整权限快照、套餐与订单查询及下单错误处理；支付仍遵循 MU 未开放的状态。接口表、调用示例、心跳和保持登录说明见 [用户系统功能层](docs/account-system.md)。

可通过 `MODDOCK_ACCOUNT_URL` 配置账号服务根地址（HTTPS，或用于测试的本机 HTTP）。协议版本沿用 MU 的 `2026-09-26`，后续 MU 更新协议时需要同步。

桌面主窗口使用沉浸式标题栏：背景延伸到窗口顶部，保留系统窗口按钮和顶部 40px 拖动区域。Windows 控制按钮使用透明底色；macOS 保留左上角交通灯。拖动区域依据 Window Controls Overlay 状态显示，网页预览不显示，独立的 Nexus 授权窗口保持原生标题栏。

登录与注册背景使用 React Bits `DriftWall`。`src/auth/steam-covers.js` 保存按 2026-10-12 Steam 官方 [Most Played](https://store.steampowered.com/charts/mostplayed) 榜选取的 18 款游戏，Steam 官方 CDN 的竖版封面已打包到 `public/covers/`，断网时也能显示；这是静态精选，不会在启动时请求榜单。背景使用固定覆盖区域，按窗口对角线补足列数与循环副本，滚动及窗口缩放均保持覆盖。封面文件损坏时尝试官方横版图，再保留游戏名称作为兜底。背景不参与键盘焦点；进入首页、页面隐藏或启用系统减少动效时停止逐帧动画。检查：`node test/ui-drift-wall.cjs`。

登录区域使用 React Bits `ReflectiveCard` 居中展示，保留整屏游戏封面背景，针对 Windows 桌面窗口验证布局。品牌放大居中，首步不展示介绍文案和预览标记。卡片通过 `children` 承载登录与验证码注册，使用默认灯光反射，不启用摄像头或视频。WebGL 不可用时保留渐变金属表面；表单不随鼠标倾斜。检查：`node test/ui-reflective-card.cjs`。

“欢迎回到游匣”和“创建你的游匣账号”使用 React Bits `Shuffle` 字符滚动，标题出现或切换登录、注册时播放一次。字体使用本地打包的 [Fusion Pixel Font](https://github.com/TakWolf/fusion-pixel-font) 简体中文版本，24px 为原生像素尺寸的两倍；字形授权及来源保存在 `public/fonts/`。启动动画结束后才播放，返回邮箱步骤时重播，减少动效时展示静态标题。拆分字符不会改变屏幕阅读器读取的标题或表单尺寸。

登录卡片的“游匣” Logo 文字使用 React Bits `FuzzyText`，保留手柄图标和 MODDOCK 字标。默认轻微抖动，悬停增强，以 30fps 绘制并适配最高 2 倍屏幕像素比。进入首页、页面隐藏或启用减少动效时展示静态字形；Canvas 不可用时保留原文字。

进入首页和返回登录使用 `GridScanTransition`：约 1.3 秒的绿色网格扫描，完全覆盖页面后交接，再显露目标页面。页面保留原始 DOM 和画布，结束后卸载扫描并释放 WebGL 资源；开启系统减少动效时直接交接，WebGL 不可用时使用 CSS 网格。摄像头、陀螺仪和人脸模型加载均关闭。依赖包括附件源码使用的 `three`、`face-api.js` 和 `postprocessing`。检查：`node test/ui-grid-scan.cjs`。

`npm run build` 使用 esbuild 生成本地 `public/auth.js` / `public/auth.css`；`npm start` 与 `npm run preview` 会先自动构建。直接运行 `node server.cjs` 时，服务会在监听端口前自动补建缺失的前端文件；修改前端源码后需要重新构建，Windows 打包前也需要运行 `npm run build`。构建产物已加入 Git 忽略。

需要 Node.js 22.15 及以上（使用内置 ZIP CRC 校验）。

```sh
npm install
npm start
```

网页预览：`npm run preview`，打开 http://127.0.0.1:4173/ 。网页预览读取的是运行 Node 的这台机器，不是浏览器所在的其他电脑。“打开位置”仅桌面版可用，网页可以另存文件。

验证：`npm test`。
安装界面检查：`node test/ui-installations.cjs`，使用 Google Chrome、独立临时下载和游戏目录；测试资源不会出现在生产游戏库。
真实接口界面与下载检查：`node test/ui-live.cjs`，需要安装 Google Chrome 和网络连接。该检查在临时目录创建 Steam 安装记录用于扫描测试，生产应用没有测试游戏。

## Windows 打包

生成 Windows x64 安装包：

```sh
npm run build
npm exec --yes --package=electron-builder@26.15.3 -- electron-builder --win nsis --x64 --publish never --config scripts/electron-builder.cjs
```

安装包输出到 `output/windows/Moddock-0.5.0-windows-x64-Setup.exe`，支持选择安装目录并创建桌面及开始菜单快捷方式。安装包未签名；生成后仍需在 Windows 实机验证安装、启动和卸载。

使用已校验的 Electron Windows x64 运行目录（含 Moddock.exe 及伴随文件），运行：

```sh
python3 scripts/package-windows.py --runtime /path/to/Moddock --output /path/to/outputs
```

脚本包含生产 ZIP 解包依赖，输出 Windows / 源码 ZIP 及 SHA-256 校验文件；排除 Git、用户数据和 node_modules 开发依赖。Windows 实机验证仍需另行进行。

## v0.5.0 NXM、待安装库、扩充规则、更新与配置档案

### Nexus 普通账号下载

1. 在设置连接自己的 Personal API Key。
2. 文件列表可先尝试“下载”。Nexus 拒绝直接签发时，下载任务显示“等待文件授权”，点击“在软件内授权”。也可从文件详情直接打开授权窗口。
3. 在软件内的官方 Nexus 页面登录同一个账号，点击该文件的 Mod Manager Download，按网站要求完成确认。生成的 nxm:// 链接由软件接收，自动继续相应任务。
4. 支持软件未启动时的命令行启动链接、已有实例回传、macOS open-url 事件。Windows 便携包首次运行会请求注册 NXM 协议；注册结果在设置显示。其他管理器可能占用关联，此时复制生成的 NXM 链接，在游匣设置选目标游戏并粘贴接收。
5. 网站签发是必需的，软件不生成授权、不绕过账号权限，也不保证网站一定接受内嵌登录。网页预览不提供官方授权窗口，可接收粘贴链接。

临时 key/expires 仅保存到本次运行内存，拒绝过期、重复参数、非文件链接、游戏专区不匹配，存在 user_id 时核对 API Key 账号。先收到链接后连接 Key 也能继续下载。不会把完整 NXM URL、API Key 或 CDN 签名写进历史或诊断；网页登录会话在 Electron 独立持久分区保存。

### 自动导入与安装模板

默认在下载及大小/可用来源 MD5 校验后，重新校验 SHA-256，安全解包读取真实文件，加入“Mod 管理 → 待安装 Mod 库”。设置中可关闭自动导入；下载管理提供手动导入或重新检查。导入失败保留完整下载文件和具体原因，RAR/7z/安装器当前不自动导入。自动导入不向游戏目录写入；安装仍通过预览和确认。

新增 Skyrim SE、Fallout 4 Data 规则与霍格沃茨、黑神话、剑星、铁拳纯 pak 目录模板，以及 BepInEx/MelonLoader 通用模板。按游戏记录和包内文件给出建议，安装规则窗口可选模板。Bethesda Data 包保留插件/资源目录，阻止 FOMOD 和可执行/加载器混合包；插件启用和排序仍需由对应游戏/加载器确认。引擎模板需要核对游戏特有路径和加载器，不等于所有游戏或包已经兼容。

### 更新与配置档案

- Mod 管理中按游戏“检查 N 网 Mod 更新”，对照当前来源文件版本与官方文件列表。数字版本较高时提示可用更新，无法可靠比较时标记需查看，连接失败单独显示。主文件优先，仍由用户核对并选择下载。非 Nexus 来源暂不检查版本更新。
- 更新文件沿用来源授权、下载校验与自动导入；现有安装保持原状。安装新版前先卸载旧版本、核对新版本方案和前置。当前不做无交互自动替换。
- “保存当前配置”记录该游戏整套托管 Mod 的启用/停用状态和默认规则，可命名多个档案。“查看并切换”先展示目标启用列表，再一次切换；档案外新加入的项停用。
- 切换预先验证游戏路径、游戏进程、前置、SMAPI 依赖、全部目标哈希及备份/载荷。用统一落盘事务执行，失败回滚整套文件和状态，重启恢复。发现外部修改或档案项已卸载/替换则拒绝。配置档案不改变插件加载顺序，不包含外部管理器或存档。

验证：`npm test`、`node test/ui-installations.cjs`、`node test/ui-features.cjs`。NXM 签发/API 响应使用独立测试数据，下载、校验、解包、安装、启停、卸载和回滚使用临时目录真实字节。尚未验证 Windows 实机协议关联、Nexus 真实账号网页登录/签发和实际游戏效果。
