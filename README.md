# 游匣 Moddock v0.5.0

### 文件组合下载与安装（0.6.9）

资源详情支持选择同一 MOD 的多个文件、调整顺序，一起下载或在全部下载完成后自动依次安装。明确的单一主文件或整合成品包会作为推荐选项；开发素材、归档旧版及分卷包不会自动参与安装。多个版本与可选内容由用户确认，安装沿用原有前置检查、文件冲突检查、校验、备份和回滚。

下载管理显示组合进度。失败时保留已下载或已安装的项目，“继续组合任务”只重试未完成部分。退出账号或关闭客户端会暂停自动安装，重新登录后需手动继续。各文件保留独立安装记录；组合不是合并压缩包，也不代表游戏内兼容性已验证。Steam 工坊继续使用 Steam 自身的订阅管理。

Windows 本机游戏库、社区 Mod 浏览下载与按游戏规则安装管理应用。

### 下载连接恢复（0.6.1）

MU 临时网页错误不会清除有效登录；安全的查询可自动重试，下载状态短暂断线时继续连接原任务。来源验证独立于下载轮询，具备超时、重连按钮和明确的加载提示。工坊使用专用游戏索引复查匹配，支持选择并保存候选专区；没有准确专区时说明来源未收录，不会自动选择名字相近的其他游戏。平台下载模式不再显示个人网页授权入口。

## 操作流程

1. 登录成功或恢复登录状态后自动读取 Steam 安装记录与游戏库（Windows 同时识别 Epic），扫描期间可继续使用界面。未找到游戏时，在设置中点击“添加游戏库”，通过系统文件夹选择器选择 Steam 游戏库、steamapps 或其中的游戏文件夹，自动识别所属库、保存并扫描。扫描位置默认折叠；移除额外位置只修改扫描范围，不删除游戏文件。
2. 进入扫描到的游戏，软件内查询 Nexus Mods、GameBanana 与 Steam 创意工坊，查看列表与总数。
3. 输入 Mod 名或关键词进行当前游戏范围的搜索。通过来源标签筛选，点击“加载更多”分页读取。不会一次把全部资源下载到本地。
4. 点击 Mod 查看描述、前置要求（来源提供时）及文件列表，选择文件后加入软件内下载队列。
5. 在“下载管理”查看进度、取消、重试、打开文件所在位置或另存。下载记录在重启后保留；未完成任务会标记中断，可重新下载。

没有本机游戏时，“我的游戏”显示空游戏库；“MOD 工坊”仍可浏览真实游戏目录。生产界面不使用演示 MOD。

## MOD 工坊（第一版）

MOD 详情会通过 translate.js 自动将介绍和前置说明翻译为简体中文，支持“查看原文 / 查看中文”切换。游戏页“探索 Mod”与 MOD 工坊共用此功能；MOD 名称、作者、下载文件和依赖名称保留原样，正文中的代码、常见路径和链接跳过翻译。译文按内容缓存，原文更新后重新翻译；翻译失败或超时保留原文，可点击“重试翻译”。首版使用 translate.js 公共翻译通道，需要联网，服务可用性和额度由公共通道决定。

MOD 工坊、收藏和游戏页“探索 Mod”的列表也会自动翻译名称与简介：中文名称下保留原名，点击原名可直接按来源原名搜索；简介通过“简介原文”展开对照。原始名称、简介、资源 ID 及收藏/下载数据不被译文覆盖。列表合并同批请求并限制翻译并发，结果只更新对应卡片，不重绘搜索输入框；服务失败时保留原文并提供单独的翻译重试。

顶栏新增“MOD 工坊”，沿用深色与绿色强调色。可切换全部游戏、我的游戏和收藏；游戏目录由已知三站游戏映射、随应用附带的 Nexus 游戏索引及本机游戏合并，支持中英文名称搜索与分页。目录不是三站完整支持清单，每个来源会独立确认是否有对应专区。

- 进入游戏专区后，Nexus、GameBanana 和 Steam 分别加载、分页和重试。可搜索当前游戏的 MOD，并按来源筛选；单站失败保留其他站点结果。
- 列表保留来源原始分类、统计口径和更新时间。分类筛选与“最近更新”排序仅作用于已加载结果，不宣称全库统一分类或跨站热度排名。
- 右侧详情抽屉展示预览图、介绍、前置和文件，关闭后继续浏览。收藏按游匣账号分别保存在本机数据目录 `workshop` 中，最多 500 项，不同步到云端。
- Nexus 和 GameBanana 下载复用现有队列。可以仅下载，之后在下载管理点击“关联游戏并安装”；只能关联扫描到的同款游戏，再核对原有安装方案。不会因为浏览或下载而写入游戏目录。
- 工坊内的 Steam 资源使用“在 Steam 中订阅”。桌面版打开 Steam 资源页，网页预览打开官方网页；订阅状态、下载和更新由 Steam 负责，游匣不把打开页面当作订阅成功。
- Nexus 下载默认通过 MU 统一服务完成，未安装游戏也可直接下载。Nexus 文件授权由后台处理，客户端无需输入 Key、登录 Nexus 或回传 NXM。

验证：`node --test test/workshop.test.cjs` 覆盖目录、分源失败、收藏隔离与持久化、未安装游戏下载后关联部署、NXM 回传。`node test/workshop-fixture.cjs` 可启动独立临时界面验证环境，使用测试账号和测试资源，不读取真实账号或游戏目录。

## 三站支持范围

- **Nexus Mods**：使用官方 GraphQL API，按游戏专区查询公开 Mod，支持关键词搜索、总数和分页。详情、前置及文件列表在软件内显示。所有已登录 MU 账号默认通过统一下载服务获取文件：后台持有平台 Nexus Key 和网站会话，完成免费账号的文件授权与来源下载，再通过 MU HTTPS 服务传输给客户端。客户端核对大小与 SHA-256，不接收 Nexus Key、Cookie、NXM 或源站签名链接。来源会话失效或出现验证时由维护方处理，客户端显示等待状态。
- **GameBanana**：按游戏查询和搜索公开 Mod，软件内获取详情、文件列表与直接下载。已实测从 GameBanana 下载真实 ZIP 文件，校验来源 MD5、文件大小及本地 SHA-256。
- **Steam 创意工坊**：按 Steam App ID 查询公开列表，兼容新版 SSR 页面与旧版卡片；也可在设置输入 Steam Web API Key 使用官方查询接口。已实时验证 RimWorld 公开列表的两页结果、总数和分页。MOD 工坊中的订阅入口交给 Steam 处理；原有游戏详情仍仅允许下载公开详情接口提供的直链。现代工坊资源的 Steam 客户端下载通道尚未接入，Steam 账号订阅与 Windows 协议跳转仍需实机验收。

资源列表、详情、下载队列、文件校验和安装管理在本软件完成。Nexus 普通页面步骤在后台自动执行；终端用户只需登录 MU 并点击下载。来源不支持或需要维护时，软件显示具体原因。

## MU 统一 Nexus 下载与来源设置

新版客户端默认调用 `https://mu-api.claude-api.cn/api/v1/nexus`，使用当前 MU 登录态，无需额外客户端配置。每个任务绑定 MU 账号，其他账号无法读取、取消或接收它的文件。私有 Nexus worker 已部署在 MU 服务器上，由用户级 systemd 维护；初始化、配额、缓存与验证记录见 [平台下载说明](docs/nexus-platform-test.md)。旧安装包需要更新客户端代码。

- Nexus 个人 Key、SSO 和 NXM 回传入口在平台模式下隐藏；已有本机 Nexus Key 不再载入，旧的授权等待任务可重新下载。
- 可选 Steam Web API Key 仍由 Electron `safeStorage` 加密保存在本机，按 MU 服务和账号隔离。它不表示登录 Steam 账号或订阅完成；公开浏览与订阅仍可直接使用。
- “退出登录”停止客户端进行中的下载并释放当前账号授权。来源设置、下载历史及诊断不保存 Nexus Key、Cookie 或签名链接。
- Nexus 后台凭证及网页登录会话仅保存在服务器的私有数据目录。维护方首次初始化会话，后续普通文件授权自动完成；网站要求重新登录或验证时需要维护方恢复。
- `MODDOCK_NEXUS_PLATFORM_CONFIG` 仅供独立本机开发试验使用，安装包不包含此私有文件。个人 SSO 实现仍保留独立测试，当前默认产品流程通过 MU 服务下载。

`test/nexus-platform.test.cjs` 验证默认 MU 下载、两个账号及任务隔离、取消、退出登录时的后台准备取消、文件大小和 SHA-256 校验；MU 服务的 HTTP 测试验证真实鉴权与当前功能权限。128 项客户端自动测试通过。Windows 系统加密与实际游戏安装仍需 Windows 客户端验收。

自动匹配使用 Steam App ID、已知专区映射及游戏英文名的唯一匹配。不能唯一匹配时，可在游戏内“来源匹配”填写 N 网专区名、GameBanana 游戏 ID、Epic 对应 Steam App ID。无法保证所有本机游戏在每个站点都有 Mod 专区。

## v0.4.0 游戏专属安装与管理

### 一键安装与恢复原生游戏

自动安装会合并所选文件说明、包内 README 和模组介绍。未命中内置规则的普通目录包，以及尚无内置规则的纯 PAK 包，可从作者明确的复制/解压目录自动生成安装方案，核对本机目录与包结构后部署和备份；无需在高级设置填写路径。“安装依据”保留来源、引用原文及实际目标。支持中英文复制/解压说明、相对目录、当前游戏的完整路径、游戏根目录标记及带空格的引号路径。需要选择版本、多目标映射、说明冲突、外部工具或无法定位路径时显示具体阻塞原因；当前解析器不保证理解任意自然语言安装教程。

普通 PAK 的说明判断区分 Blueprint 资源与 Blueprint Loader：描述角色蓝图、动画或物理资源不会被当作加载器前置。明确要求 UE4SS、Blueprint Loader、LogicMods 等时保留专用流程检查，并显示对应原文；可选或明确无需的加载器不阻止普通 PAK。仅有工具名称、无法确定其作用时交给 AI 后备进一步分析。严阵以待可按作者明确路径选择 `ReadyOrNot/Content/Paks/mods`。

普通规则和目录解析无法确定方案时，自动复用工程的 MU / pi agent 通道分析说明、包内文件列表和本机相对目录清单。AI 通过现有 custom-project 协议返回 installation-plan.json，由本地引擎验证逐文件映射、作者引用、完整覆盖、前置、目标冲突及哈希，再备份安装。支持按作者明确说明分配多个目标目录；不执行 AI 命令，不生成或运行安装脚本，不绕过 FOMOD、加载顺序、外部用户目录等专用流程。使用现有 Pro AI 权限，无需填写 Key。AI 阶段超时、退出登录、账号切换、无效结果或无法确认目录时停止；写入中切换账号会回滚。安装依据保留 pi agent 标识、引用原文及输入摘要。此功能不会把文件部署等同于游戏内生效。

下载完成后点击“一键安装”，自动关联唯一匹配的本机游戏，并根据已核对的游戏/加载器规则、包内布局、作者文件说明与前置选择安装方式。当前覆盖 SMAPI、Cyberpunk legacy archive、霍格沃茨/严阵以待/黑神话/剑星/铁拳的普通 PAK、明确布局或作者目录说明的 BepInEx 5 与 MelonLoader 包。不会用任意 Paks 目录、DLL 后缀或已有顶层目录猜测安装方式；Bethesda 插件启用/排序、REDmod、UE4SS 与混合框架包仍需专用适配。每个包独立选择规则，覆盖已有文件时自动备份，写入失败回滚。规则、资料链接和实际目标可在“安装依据”中查看；完整支持范围及来源见 [安装规则核对](docs/install-rules-2026-10-14.md)。高级设置保留手动规则与安装预览。

游戏详情和 Mod 管理提供“恢复原生游戏”：一次移除该游戏全部已启用及已停用的托管 MOD、还原被替换的原始文件，整套操作使用可恢复事务。存档、截图、用户设置及未托管文件保留在原处；修改过的托管文件先按实际 SHA-256 单独保存到数据目录 `installations/user-files/<恢复编号>`，结果显示保存位置和数量。操作只根据托管记录处理具体文件，不清空游戏目录，不移除外部管理器安装的 MOD 或手动安装的加载器。

手动安装规则、包内文件查看及安装预览收纳在“高级设置”，以下规则说明适用于自定义安装。

所有扫描到的游戏都可以建立自己的安装规则，并非只允许几款游戏安装。**这不等于所有游戏、任意 Mod 都能自动适配或保证生效**：规则需要符合该游戏和该包的作者说明。未知游戏在游戏详情或下载管理中打开“安装规则”。

1. 下载完成后点击“安装”。没有规则时在软件内查看包内实际文件，设置游戏内容根目录、包内目录、目标目录、前置文件和游戏/加载器启动入口。所有路径均为相对目录，不接受越出扫描游戏目录的写入。
2. 安装方案列出每个源文件 → 目标文件，标明新建或已有文件覆盖。核对作者说明；覆盖已有文件必须明确勾选备份替换。
3. 安装时再次检查游戏路径、前置、游戏进程、文件冲突、下载 SHA-256 和暂存文件哈希。替换前备份原文件，记录每个托管文件和目标哈希。
4. “Mod 管理”支持启用、停用、卸载和校验。停用/卸载还原被替换的原文件，移除自己新增的文件；保留游戏或 Mod 后续生成的未托管文件。托管文件被外部修改时拒绝操作并列出路径，避免误删用户改动。此时先保留改动，恢复记录中的文件版本后重试；本版没有强制覆盖按钮。
5. 游戏详情点击“开始游戏”，或在 Mod 管理点击“运行验证”，打开启动前 MOD 管理弹窗。默认勾选已启用项，可逐项勾选、全选或全部取消；选中的已下载待安装包先按现有自动安装规则安装，再整套应用启停状态并启动。选择保留到下次启动，取消弹窗不更改文件。安装失败时停止启动；已有 MOD 的启停失败会回滚，游戏平台启动请求失败时恢复此前启停状态。已成功安装的新包会保留，可在弹窗中重试或管理。
6. 桌面端普通 Steam / Epic 游戏默认通过所属平台启动，无需手填路径；SMAPI MOD 自动使用加载器入口，手动配置的原生入口优先。Epic 使用[官方协议激活说明](https://assets-unreal2-epic-prod-us2.s3.dualstack.us-east-1.amazonaws.com/original/4X/f/c/4/fc4342c50e1a0abf34943e019ee90bacccc62950.pdf)支持的安装路径启动。平台启动仅表示已提交启动请求，不跟踪平台所创建的游戏进程。自定义入口可配置相对日志路径及实际加载成功标记；点击“检查本次运行”读取进程和本次日志，SMAPI 匹配本次 Loaded mods/content packs 列表中的托管 MOD 名称和版本。网页预览不调用系统游戏平台，需桌面端或自定义原生入口。

### 安装规则类型

| 规则 | 实际行为与要求 |
| --- | --- |
| 目录映射 / 原文件替换 | 适用于任意游戏可按目录部署的 ZIP；可选包内目录，保持其子目录结构，支持备份替换。例如 XNB 替换包可指定包内内容目录映射到游戏 Content。必须按作者说明配置。 |
| SMAPI 清单包 | 找出 manifest.json，检查 UniqueID、入口 DLL、必需依赖/版本、清单声明的最低版本；部署到 Mods/UniqueID。阻止重复 ID、依赖缺失、停用被其他启用 Mod 依赖的项；重新启用时再次检查依赖。星露谷有内置目录预设，SMAPI 必须先正确安装；本版不代替官方 SMAPI 安装程序。 |
| 纯 archive 包 | 只部署 archive 文件，验证 RDAR 头，忽略文档/图片，混合其他框架文件则拒绝。赛博朋克 2077 有 archive/pc/mod 目录预设；不是 REDmod/ArchiveXL/REDscript 等框架安装器。 |
| Unreal pak/utoc/ucas | 将对应数据文件按文件名放入你配置的游戏 Mod 目录。引擎版本、签名、配套文件、游戏是否开放 Mod 加载需要按作者说明确认，不能只凭扩展名判断可用。 |
| BepInEx 插件目录 | 按配置的包内目录 → 目标目录部署，检查 BepInEx/core/BepInEx.dll 存在；BepInEx 本身的游戏版本、架构、IL2CPP/Mono 配置仍需正确。本版不会代装加载器或自动识别所有插件依赖。 |

支持 ZIP、Windows 7z 和独立 archive/pak/utoc/ucas，解包格式按真实文件头识别，兼容被来源误标为 .zip 的 7z 包。新下载的包按实际格式保存扩展名；既有下载无需改名或重新下载。7z 使用随包独立解压组件，先校验清单，再逐文件流式提取、核对大小和 CRC；不跟随包内链接，不执行安装脚本。RAR4/RAR5 与声明式 FOMOD 选项安装已接入，详见 [FOMOD 安装说明](docs/FOMOD.md)。脚本安装、外部部署工具仍需专用适配。内置目录预设只是便捷规则，不是全 Mod 兼容认证。同一游戏存在多种安装机制时可以通过“包内目录/目标目录”分别选择；每游戏保存当前默认规则；每项已安装 Mod 单独保存安装时的规则快照。可以调整默认规则，为下一种格式生成方案，已有 Mod 仍按自己的规则停用或卸载。跨规则碰撞到同一目标文件时仍拒绝安装。

### 校验与恢复

- 大型 Mod 安装限制：安装包最多 128 GiB，最多 200000 条目（含目录），解压合计 256 GiB，单文件 128 GiB；解压后大于 1 MiB 的 ZIP 文件条目膨胀倍数最多 2000 倍。超限提示包含具体检查项、文件名、实际值和上限；验证 ZIP CRC/展开大小、拒绝链接、路径穿越、Windows 保留名、大小写重名。
- 同目标文件的托管 Mod（包括停用项）互相排斥；本版不做冲突排序、自动合并或覆盖栈。同一下载项再次安装、SMAPI 重复 ID 会阻止；更新通过卸载旧版再安装新版。
- 写入使用临时文件、事务日志和原文件备份。中途失败回滚；下次启动恢复未完成事务。回滚期间发现外部文件改动则保留日志和备份，停止自动恢复并报告原因。文件系统损坏、进程竞争或突然断电仍无法保证无损；不要同时用多个 Mod 管理器改同一目录。
- **文件部署成功 / 文件校验通过 / 进程运行中 / 日志确认加载 / 游戏内效果确认分开表达**。进程正常或通用日志标记出现不能保证每个 Mod 生效；需要存档、场景、版本等实际游戏条件。本版没有自动游玩检查。
- Windows 用系统进程列表检查游戏路径和已配置入口，无法读取部分受保护进程的路径时可能漏检；请退出游戏再部署。需管理员权限的游戏目录会报告权限错误，不自动提权。
- 安装记录、载荷和原文件备份在数据目录 installations 中，启用/停用和重启后保留。正常卸载后移除该项载荷/备份；不删除未托管文件或非空游戏目录。

验证：自动检查（临时目录实际文件操作）及 `node test/ui-installations.cjs` 完整界面流程通过。**尚未在 Windows 实机或实际游戏中验证 Mod 效果**。这些检查证明部署与恢复逻辑，不代表所有游戏和 Mod 兼容。

## 数据与下载

桌面版：Electron 用户数据目录下的 `data`，具体下载目录在设置中显示。
网页预览：项目 `.moddock-data`。可通过 `MODDOCK_DATA` 指定数据根目录。

最多同时下载 3 个文件、队列 20 项，单文件上限 128 GiB，与安装包上限一致。临时文件以 `.part` 保存，完成后校验大小，生成 SHA-256；来源提供 MD5 时比对。失败或取消清理未完成文件。

来源 Key 在桌面版使用本机系统加密保存，在网页预览仅存于内存；NXM 文件临时授权始终仅存于内存。不将密钥写入设置、下载历史或返回给界面。下载直链在本地服务取得，不接受用户输入的任意 URL；重定向验证允许的 HTTPS 来源域名；拒绝网页或 JSON 伪装的下载内容。

## 源码运行

### MU 账号登录与注册

启动后先展示登录页。登录按“邮箱 → 密码”分两步，注册按“邮箱 → 密码 → 邮箱验证码”分三步，每步只有一个输入框，可返回上一步修改。步骤切换使用约 330 毫秒的滑动和淡入淡出，返回时反向播放；动画期间阻止重复提交，结束后聚焦当前输入框，系统减少动效时直接切换。登录与注册在同一卡片内切换，保持页面地址、卡片尺寸和背景；保留密码显隐、验证码错误清空和重发倒计时。完整验证码验证通过后自动注册，并用 React Bits `GridScan` 进入首页，无需再点击确认。必须登录后才能使用，首页侧栏的返回按钮会退出登录并回到账号入口。

账号界面只在输入错误、验证码过期或处理中显示当前提示。验证码步骤的 `?` 可主动展开收件帮助和有效期，再次点击或按 Escape 收起，帮助不会改变卡片尺寸。注册前需勾选用户协议和隐私政策，桌面版通过系统浏览器打开 MU 的协议页面。

登录的“输入密码”步骤提供“找回密码”。找回流程沿用分步卡片：确认邮箱 → 新密码 → 确认新密码 → 邮箱验证码，发送验证码使用 MU 的 `purpose: reset`，完整验证码填写后提交 `auth/reset-password`。密码需 8–128 位，两次一致；发送失败和验证码错误保留已填写内容，返回修改时保留原验证码及重发倒计时。重置成功后清空密码并返回同一邮箱的登录密码步骤，提示使用新密码重新登录，不会自动进入游戏库。

默认复用 `https://mu-api.claude-api.cn/` 的 MU 账号服务，已有 MU 账号可直接登录。密码为 8–128 位，邮箱验证码有效期 10 分钟，重发倒计时遵循服务端响应。发送验证码调用 `POST /api/v1/auth/code`（`purpose: register`）；填写完整验证码后直接调用 `POST /api/v1/auth/register`，由 MU 验证并创建账号，无单独验证码校验接口。登录调用 `POST /api/v1/auth/login`。错误密码、验证码无效、限流、账号停用和维护提示使用服务端状态与文案。

React 入口为 `src/main.jsx`，认证适配器为 `src/auth/client.cjs`。`account.cjs` 经本地服务代理 MU 请求，避免浏览器跨域；MU 令牌不返回界面，密码不保存。默认仅在服务内存中保存会话；桌面版可通过 `remember: true` 将刷新令牌保存到系统加密缓存，保存失败会返回提示。界面仅持有 HttpOnly / SameSite Cookie 对应的随机会话标识。页面刷新会校验账号，访问令牌即将到期或返回 401 时串行刷新；退出、改密和密码重置会清除对应会话。本地业务接口和 NXM 接收均要求登录，关键操作按 MU 的游戏库、配置和启动权限实时授权。原生游戏库由 `public/app.js` 提供挂载/卸载入口。

登录后可从顶部账号菜单打开“个人中心”，以可拖动、翻面的挂绳卡片查看 MU 邮箱、账号名称、用户 ID、会员等级及有效期；每次打开时刷新账号信息。弹窗打开时暂停游戏库轮询，关闭后恢复，支持 Escape、关闭按钮和点击背景退出，并将焦点归还账号菜单。退出登录也位于账号菜单。界面使用 `src/account/UserCenter.jsx` 与账号状态模块 `src/account/store.cjs`。

用户系统功能层还提供完整权限快照、套餐与订单查询及下单错误处理；支付仍遵循 MU 未开放的状态。接口表、调用示例、心跳和保持登录说明见 [用户系统功能层](docs/account-system.md)。

可通过 `MODDOCK_ACCOUNT_URL` 配置账号服务根地址（HTTPS，或用于测试的本机 HTTP）。协议版本沿用 MU 的 `2026-09-26`，后续 MU 更新协议时需要同步。

桌面主窗口使用沉浸式标题栏：背景延伸到窗口顶部，保留系统窗口按钮和顶部 40px 拖动区域。Windows 控制按钮使用透明底色；macOS 保留左上角交通灯。拖动区域依据 Window Controls Overlay 状态显示，网页预览不显示，独立的 Nexus 授权窗口保持原生标题栏。

登录与注册背景使用 React Bits `DriftWall`。`src/auth/steam-covers.js` 保存按 2026-10-12 Steam 官方 [Most Played](https://store.steampowered.com/charts/mostplayed) 榜选取的 18 款游戏，Steam 官方 CDN 的竖版封面已打包到 `public/covers/`，断网时也能显示；这是静态精选，不会在启动时请求榜单。背景使用固定覆盖区域，按窗口对角线补足列数与循环副本，滚动及窗口缩放均保持覆盖。封面文件损坏时尝试官方横版图，再保留游戏名称作为兜底。背景不参与键盘焦点；进入首页、页面隐藏或启用系统减少动效时停止逐帧动画。检查：`node test/ui-drift-wall.cjs`。

登录区域使用 React Bits `ReflectiveCard` 居中展示，保留整屏游戏封面背景，针对 Windows 桌面窗口验证布局。品牌放大居中，首步不展示介绍文案和预览标记。卡片通过 `children` 承载登录与验证码注册，使用默认灯光反射，不启用摄像头或视频。WebGL 不可用时保留渐变金属表面；表单不随鼠标倾斜。检查：`node test/ui-reflective-card.cjs`。

“欢迎回到游匣”和“创建你的游匣账号”使用 React Bits `Shuffle` 字符滚动，标题出现或切换登录、注册时播放一次。字体使用本地打包的 [Fusion Pixel Font](https://github.com/TakWolf/fusion-pixel-font) 简体中文版本，24px 为原生像素尺寸的两倍；字形授权及来源保存在 `public/fonts/`。启动动画结束后才播放，返回邮箱步骤时重播，减少动效时展示静态标题。拆分字符不会改变屏幕阅读器读取的标题或表单尺寸。

登录卡片的“游匣” Logo 文字使用 React Bits `FuzzyText`，保留手柄图标和 MODDOCK 字标。默认轻微抖动，悬停增强，以 30fps 绘制并适配最高 2 倍屏幕像素比。进入首页、页面隐藏或启用减少动效时展示静态字形；Canvas 不可用时保留原文字。

进入首页和返回登录使用 `GridScanTransition`：约 1.3 秒的绿色网格扫描，完全覆盖页面后交接，再显露目标页面。页面保留原始 DOM 和画布，结束后卸载扫描并释放 WebGL 资源；开启系统减少动效时直接交接，WebGL 不可用时使用 CSS 网格。摄像头、陀螺仪和人脸模型加载均关闭。依赖包括附件源码使用的 `three`、`face-api.js` 和 `postprocessing`。检查：`node test/ui-grid-scan.cjs`。

交互动效由 `src/motion/` 统一管理：`transition-hook` 驱动表单步骤、开屏退出、个人中心、来源引导和折叠表单；原生 DOM 页面与 Mod 弹窗使用同一节奏的 Web Animations。页面入场只在切换时播放，轮询更新保留正在播放的内容容器；减少动态效果时直接切换。`transition-hook@1.5.2` 的上游 peer 范围仍为 React 16/17，`package.json` 只对该包覆盖为项目的 React 19 依赖；升级 React 或该库时需复查进出场、快速开关和焦点恢复。

`npm run build` 使用 esbuild 生成本地 `public/auth.js` / `public/auth.css`；`npm start` 与 `npm run preview` 会先自动构建。直接运行 `node server.cjs` 时，服务会在监听端口前自动补建缺失的前端文件；修改前端源码后需要重新构建，Windows 打包前也需要运行 `npm run build`。构建产物已加入 Git 忽略。

需要 Node.js 22.15 及以上（使用内置 ZIP CRC 校验）。

```sh
npm install
npm start
```

网页预览：`npm run preview`，打开 http://127.0.0.1:4173/ 。网页预览读取的是运行 Node 的这台机器，不是浏览器所在的其他电脑。“打开位置”仅桌面版可用，网页可以另存文件。

验证：`npm test` 执行自动测试；`npm run test:ui` 会先构建界面，再执行独立测试数据下的完整界面回归，需要安装 Google Chrome。`npm run test:all` 顺序执行两者。测试资源使用独立临时下载和游戏目录，不会出现在生产游戏库。
真实接口界面与下载检查：先运行 `npm run build`，再运行 `npm run test:ui:live`，需要 Google Chrome 和网络连接。该检查在临时目录创建 Steam 安装记录，真实来源的文件与列表变化可能影响结果。

游戏库状态在空闲时每 15 秒刷新；下载排队、传输、文件授权或 Nexus SSO 进行中时每 700 毫秒刷新。页面隐藏、个人中心打开及扫描期间暂停自动轮询；页面恢复可见或关闭个人中心时立即刷新，连续失败按指数退避，最长间隔 60 秒。手动操作仍立即更新结果。

安装包输出到 `output/windows/Moddock-0.5.0-windows-x64-Setup.exe`，支持选择安装目录并创建桌面及开始菜单快捷方式。安装包未签名；生成后仍需在 Windows 实机验证安装、启动和卸载。

使用已校验的 Electron Windows x64 运行目录（含 Moddock.exe 及伴随文件），运行：

```sh
python3 scripts/package-windows.py --runtime /path/to/Moddock --output /path/to/outputs
```

脚本包含生产 ZIP 解包依赖，输出 Windows / 源码 ZIP 及 SHA-256 校验文件；排除 Git、用户数据和 node_modules 开发依赖。Windows 实机验证仍需另行进行。

## v0.6.0 跨游戏创作环境

所有本机游戏共用诊断、创作、校验、安装与反馈流程。环境管理按游戏文件、程序架构和专用配置选择组件：BG3 Script Extender、Unity Mono 的 BepInEx 5、悟空的 UE4SS 专用配置、已登记 RE Engine 游戏的 REFramework，以及星露谷的 SMAPI / Content Patcher。Unity IL2CPP、未登记的 Unreal 专用配置、Godot、Bethesda 等尚未接通自动创作打包的路线保留方案/源码能力，并显示缺少的适配；不会标成已经实机兼容。

UE4SS 与 REFramework 使用内置 Lua 编译器。Windows x64 首次 C# 创作会按需自动准备 Microsoft SDK，引用本机游戏程序集编译，用户无需配置编译路径。SMAPI 前置来自官方发布；Content Patcher 通过 MU 平台的官方 Nexus 文件通道获取，客户端不保存个人 Nexus Key。所有组件采用来源、哈希、游戏路径与权限校验；冲突时保留用户文件。

多游戏架构和组件安装验证不等于所有游戏或版本已通过实机测试，玩法效果仍需游戏内确认。

## v0.5.0 NXM、待安装库、扩充规则、更新与配置档案

### Nexus 平台下载

1. 登录 MU，在 Nexus 文件列表点击“下载”；平台模式不提供个人 Nexus 连接入口。
2. 后台需要文件授权时，自动进入对应文件的管理器下载页、选择 Slow download 并等待站点倒计时。
3. 后台收到对应 NXM 后获取来源字节，客户端经 MU 服务接收文件并校验大小和 SHA-256。
4. 来源网站要求登录或验证时，由维护方恢复后台会话，终端用户无需操作 Nexus 页面。
5. 历史个人账号协议处理仍有独立测试；当前默认流程由后台接收 NXM，不依赖客户端 Windows 协议回传。

后台的临时 key/expires 仅保存在本次运行内存，拒绝过期、重复参数、非文件链接及游戏专区不匹配，存在 user_id 时核对平台 API Key 账号。不会把完整 NXM URL、API Key 或 CDN 签名写进历史或诊断；网页登录会话在后台 Electron 独立持久分区保存。

### 自动导入与安装模板

默认在下载及大小/可用来源 MD5 校验后，重新校验 SHA-256，安全解包读取真实文件，加入“Mod 管理 → 待安装 Mod 库”。设置中可关闭自动导入；下载管理提供手动导入或重新检查。导入失败保留完整下载文件和具体原因，ZIP/7z/RAR 均可安全检查导入，FOMOD 在安装时展示选项。自动导入不向游戏目录写入；默认点击“一键安装”后自动选择规则、备份并部署，高级设置仍提供手动预览和确认。

新增 Skyrim SE、Fallout 4 Data 规则与霍格沃茨、黑神话、剑星、铁拳纯 pak 目录模板，以及 BepInEx/MelonLoader 通用模板。按游戏记录和包内文件给出建议，安装规则窗口可选模板。Bethesda Data 包保留插件/资源目录，阻止 FOMOD 和可执行/加载器混合包；插件启用和排序仍需由对应游戏/加载器确认。引擎模板需要核对游戏特有路径和加载器，不等于所有游戏或包已经兼容。

### 更新与配置档案

- Mod 管理中按游戏检查 Nexus / GameBanana 更新。Nexus 优先比较主文件数字版本；GameBanana 保存作者更新时间、所选文件上传时间、来源版本与 MD5，对照当前文件列表。新文件无法证明是替代版本时提示需核对，页面修改不直接认定为文件升级，来源错误单独显示。旧记录缺少比较依据时提示核对。更新结果不代表与当前游戏版本兼容。
- Steam 构建号保存在数据目录的 `game-builds.json`：首次启动或扫描建立基线，之后启动或重新扫描发现变化时，在游戏库、游戏详情和 Mod 管理显示持续兼容性提醒，列出托管 Mod 与检测到的加载器，并可一键检查 Mod 更新。临时离线或缺少构建号时保留上次记录；首次启用无法追溯此前发生的更新。加载器需核对官方兼容说明，软件不会自动替换。
- 更新文件沿用来源授权、下载校验与自动导入；现有安装保持原状。安装新版前先卸载旧版本、核对新版本方案和前置。当前不做无交互自动替换。
- “保存当前配置”记录该游戏整套托管 Mod 的启用/停用状态和默认规则，可命名多个档案。“查看并切换”先展示目标启用列表，再一次切换；档案外新加入的项停用。
- 切换预先验证游戏路径、游戏进程、前置、SMAPI 依赖、全部目标哈希及备份/载荷。用统一落盘事务执行，失败回滚整套文件和状态，重启恢复。发现外部修改或档案项已卸载/替换则拒绝。配置档案不改变插件加载顺序，不包含外部管理器或存档。

验证：`npm test`、`node test/ui-installations.cjs`、`node test/ui-features.cjs`。NXM 签发/API 响应使用独立测试数据，下载、校验、解包、安装、启停、卸载和回滚使用临时目录真实字节。尚未验证 Windows 实机协议关联、Nexus 真实账号网页登录/签发和实际游戏效果。
